# Miora 首页头部节日主题｜后台定时投放需求

> v0.1 评审稿｜2026-11-02（北京时间）
> 类型：Feature｜范围：Web 国内版与海外版首页头部｜优先级：建议 P1，待排期｜不涉及计费｜处理人待确认。
> 本稿定义建议行为，尚未开发、部署或生产验收。

## 1. 需求概览

让运营提前配置每个国家／地区的节日主题资源与当地上线、下线时间，系统自动换算时区并执行切换；到期后恢复日常资源，不需要跨时区人工值守。

以用户提供的“品牌标语＋吉祥物＋节日场景”头部运营位为业务范围。现有代码中的 Hero Logo、Hero Banner 与吉祥物是不同配置，最终槽位需研发按截图定位。本期不扩展到所有首页运营卡，不做促销、活动落地页、自动判断宗教信仰或每年无限重复排期。

| 需求 | 本期改动 |
| --- | --- |
| R1 | 管理日常资源、节日主题资源及本地版本 |
| R2 | 按国家／地区独立选择资源、投放时区和起止时间 |
| R3 | 校验排期并自动上下线，排期之间不互相覆盖 |
| R4 | 按国家命中，支持语言适配与默认兜底 |
| R5 | 预览、紧急下线、异常反馈与操作记录 |

## 2. 核心流程

运营新增主题草稿 → 绑定已验收资源 → 选择国家／地区 → 填写当地时间与时区 → 查看北京时间对照和国家预览 → 校验并确认排期 → 到点自动上线 → 到点恢复日常资源（若下一条恰好开始，则直接展示下一条）。

“保存草稿”不生效，“确认排期”才授权自动生效。设计日历是计划来源，不自动导入或自动发布。本期通过规则说明与字段清单评审，不交付可执行原型；用户截图作为业务定位参考，资源槽位核实后再补后台视觉稿。

## 3. 功能与规则

### R1 资源管理

运营在首页头部配置中维护日常资源与节日主题，可复用一个主题的多个国家变体。

| 配置项 | 规则 |
| --- | --- |
| 主题名称、节日年份 | 必填，例如“2027 春节”；复制到下一年生成草稿，需重新确认节日日期 |
| 动画与静态兜底 | 静态兜底必填；动画可选。支持的资源格式、体积、尺寸沿用经前端确认的实际槽位能力，不能仅上传链接就视为验收通过 |
| 国家本地版 | 同主题可有国家独立资源；修改共享资源时显示受影响国家。已排期版本固定，后续编辑不悄悄影响已确认投放 |
| 语言与深浅主题 | 按现有首页能力提供变体；缺失语言文案回退无文字或通用版，不能显示另一国家的节日资源 |
| 日常资源 | 每个国家可覆盖；未配置时继承全局日常资源。全局日常静态图必须可用，不能删除正在兜底的版本 |

**交互**：本期主题更换保留原有首页交互，默认静音、不新增跳转或促销承诺；动画失败使用本主题静态，静态也失败则回日常。

### R2 国家与时间配置

运营可多选国家批量建立排期，再逐国家调整资源与日期；后台展开显示每个国家的实际排期，不强制所有国家同一天上下线。

必填字段：国家／地区、主题资源版本、开始日期时间、结束日期时间、投放时区。附加字段：运营备注、资源预览链接、负责人。列表显示：本地起止、北京时间对照、当前状态与最近执行结果。

一期推荐“每个国家一个明确投放时区，全国同一时刻切换”。美国、加拿大、澳大利亚、巴西、印尼等多时区国家须显式选择 IANA 时区，不能显示含糊的“当地时间”。例如美国选择 `America/New_York` 后，该国家全部用户按纽约时间统一切换，不承诺洛杉矶也在 00:00 切换。如业务要求每个用户所在地午夜切换，需扩为按地区／时区投放，本期不混用两种语义。

| 时间规则 | 预期行为 |
| --- | --- |
| 自动算时差 | 根据所选时区在开始日和结束日分别换算北京时间，不以当前固定 UTC 偏移计算未来时间 |
| 起止边界 | 开始时刻包含、结束时刻不包含；结束必须晚于开始 |
| 夏令时 | 使用日期对应偏移。不存在的当地时刻阻止确认并提示换时间；重复出现的时刻必须明确选择偏移并预览北京时间 |
| 未来排期 | 开始必须在当前服务器时间之后；过去日期不能静默当作立即上线。确需立即上线通过单独操作确认 |
| 日期不确定 | 日期仍标暂定或未通过本地审核的主题允许保存草稿，不允许确认排期 |
| 年度变化 | 固定具体年份日期，不以“每年同月同日”处理农历、宗教历和浮动节日 |

时间示例（供验收，非实际排期）：纽约 2026-11-26 00:00 对应北京时间 11 月 26 日 13:00；纽约 2027-07-04 00:00 对应北京时间 7 月 4 日 12:00。不能全年固定加 13 小时。

### R3 排期校验与自动执行

同一国家、同一运营位任一时刻只能有一个节日主题。一期采用重叠阻断，不设置隐含优先级。

- 草稿可暂存冲突；确认排期时展示冲突国家、主题与交叠时间，阻止冲突记录生效。相邻排期 A 结束＝B 开始允许衔接。
- 批量确认时先逐国家校验，任何一项失败则本批均不确认，保留草稿和错误明细，避免运营误认为所有国家已完成。
- 状态区分草稿、待上线、展示中、已结束、已取消；执行异常单独显示，不能把时间已到但执行失败显示成成功。
- 到开始时间自动生效；到结束时间停止命中并恢复该国日常资源，没有国家日常时回全局日常。相邻 B 已开始则直接展示 B，不恢复旧主题。
- 修改已确认的未来排期，需要重新预览并确认；修改展示中的资源、国家或时间，明确影响范围后确认立即生效。旧结束任务不得误下线新版本。
- 取消未来排期后不再自动上线；主题结束、取消或紧急下线后，任务重试均不得重新激活它。

建议验收目标：健康服务下，新打开／刷新页面在边界后 60 秒内显示正确主题；已打开且可见页面也在 60 秒内更新。后台切回前台时先刷新判定；不因浏览器长期挂起承诺精确实时。

### R4 国家命中与默认资源

建议优先复用账号绑定国家／地区，与现有注册选区能力一致。该规则需产品确认后冻结，不以界面语言、浏览器时区直接当作国家。

| 用户情况 | 建议命中方式 |
| --- | --- |
| 登录且有有效绑定国家 | 使用账号国家；临时旅行或修改系统时区不改变国家主题 |
| 未登录或未绑定 | 使用服务端可提供的可信国家识别结果；当前 IP 国家能力待研发确认。无结果时展示全局日常，不把浏览器时区推测当确定国家 |
| 国内独立站点 | 可使用经确认的站点市场为中国大陆兜底；具体站点规则待确认，海外站不默认成美国 |
| 登录后国家变化 | 重新匹配账号国家并更新，不继续用访客缓存串国家 |
| 切语言 | 只切该国家主题的语言版本，不因选日语改投日本节日 |
| 未开放或无排期国家 | 显示可用日常资源；国家主题不会自动继承其他国家主题 |
| 账号国家确实变更 | 下一次有效配置读取重新匹配；本需求不新增账户国家修改入口 |

国家配置选项应来自生产有效开放名单或经产品批准的投放国家目录，不能直接使用时区映射字典。名单新增不会自动加入已有主题；名单移除时提示相关排期，停止对该市场节日投放并回日常。

### R5 预览、人工控制与异常

- 预览支持国家、界面语言、模拟当地时间、深浅主题和宽窄屏；清楚显示“预览”，不修改线上状态。
- 确认页展示受影响国家、本地时区、北京时间、资源版本、冲突及日常兜底，供运营最后核对。
- 有发布权限的运营可立即上线一个已验收版本，必须设结束时间；存在当前主题时明确替换并取消被替换排期的后续自动行为，不能静默覆盖。
- “立即下线”立刻取消当前主题的剩余展示，回日常；“紧急停用节日主题”按国家生效，期间保留排期但不展示。解除时列出将恢复的当前有效排期，确认后才恢复。
- 本期沿用后台现有权限，区分可查看／预览、编辑草稿、确认排期／紧急操作，现有权限模型待研发核对。无权限不能通过接口绕过。
- 记录操作者、操作时间、修改前后内容、国家、资源版本和执行结果，支持排查“应该显示什么／实际显示什么”。执行失败在列表明确标红并显示原因，通知接现有运营告警渠道，接收人待确认。
- 配置或资源失败时：首页回日常，输入框与导航仍可用；已过期节日即使有旧缓存也不能继续展示。无网络且页面暂停期间不作硬实时保证，恢复后立即重新判定。
- 服务恢复时按当前有效时间窗口恢复，不补播已经结束的节日。重复执行不会重复发布或错误恢复历史版本。

## 4. 待确认项与实施边界

| 待确认 | 影响与确认方 |
| --- | --- |
| 当前生产开放国家名单 | 阻塞最终投放范围；产品／后端提供生产配置，不能用前端映射替代 |
| 目标资源槽位、格式与规格 | 阻塞资源接入；前端按用户截图定位，不将 Hero Banner 能力误套 Logo 位 |
| 多时区国家用全国统一时区还是用户当地午夜 | 本稿推荐前者；产品／运营确认后冻结 R2 |
| 访客国家来源及账号国家优先级 | 阻塞精准访客投放；无法识别时日常兜底不阻塞首页 |
| 60 秒切换目标与告警负责人 | 研发／测试／运营评估确认；区分排期时间和实际执行结果 |
| 设计排期的日期与文化审核 | 未终核的节日不能确认上线；本地运营负责 |
| 现有发布版本语义 | 当前单例资源发布可能替换全局版本，需改造为国家与时间可并存，不直接复用一键发布替换所有国家 |

## 5. 验收标准

| 编号 | 关联 | 前提／操作 | 可判断的预期结果 |
| --- | --- | --- | --- |
| AC-01 | R1/R3 | 完整资源保存草稿，等待原拟上线时刻 | 线上不变；只有确认排期后才执行 |
| AC-02 | R2/R4 | 为中美配置不同资源和起止；分别访问 | 各国家命中自己的排期，不互相覆盖 |
| AC-03 | R2 | 配置纽约冬季与夏季两个示例 | 北京时间分别为 13:00 与 12:00，保存回读一致 |
| AC-04 | R2 | 选择夏令时不存在／重复当地时间 | 不存在时阻止；重复时要求明确偏移，换算结果可核对 |
| AC-05 | R3 | A 结束＝B 开始；在边界前后观察 | 无重叠、无空档；边界后命中 B，不被 A 结束任务清掉 |
| AC-06 | R3 | 同一国家创建重叠排期后确认 | 明确指出冲突且不生效；其他国家同时间可独立排期 |
| AC-07 | R1/R3 | 当前节日到期且无下一主题 | 60 秒目标内恢复该国日常；无该国日常则回全局日常 |
| AC-08 | R4 | 同账号切语言、改浏览器时区后刷新 | 仍使用账号国家，只切文案变体 |
| AC-09 | R4 | 无国家信息访客访问，再登录绑定国家账号 | 先显示全局日常；登录后重新命中正确国家 |
| AC-10 | R3/R5 | 取消未来排期或紧急下线，再触发旧任务重试 | 不重新上线；不误伤其他国家和新版本 |
| AC-11 | R1/R5 | 模拟动画、静态资源、配置获取分别失败 | 依次降级静态／日常；输入框可用，无过期主题滞留 |
| AC-12 | R3/R5 | 服务错过上线时刻后恢复 | 仍有效则恢复当前主题；已过期不补播，执行记录可见 |
| AC-13 | R5 | 无发布权限者确认排期；有权限者预览 | 前者被拒绝；后者预览不改变生产 |
| AC-14 | R3/R5 | 页面持续打开跨越开始／结束，再后台挂起返回 | 可见页面按 60 秒目标更新；恢复前台重新判定 |
| AC-15 | R2/R3 | 批量提交中一国有冲突；编辑已排期版本 | 本批无部分生效；修改重新确认且旧任务不覆盖新版本 |
| AC-16 | R5 | 按国家紧急停用，等待另一排期开始，再解除 | 停用期间保持日常；解除前说明将恢复的主题，经确认才恢复 |

## 6. 研发关注（轻量交接）

**已读源码，不等于线上已部署。** 本轮基于缓存主干 `11ee1537`（提交日期 2026-10-31；本次读取 2026-11-02）以及本地检出 `8432466f`；CNB 域名连接失败，未刷新最新远端。

- 已在缓存主干读取 `config-section-shell.tsx`：`alwaysEffectivePayload` 将 `start_at`/`end_at` 设 null，注释明确不使用定时生效。不能因数据库已有字段就认为定时投放已支持。
- 缓存主干 `hero-logo-tab.tsx` 使用 `home_hero_logo` 单例图和显隐；`hero-mascot-tab.tsx` 是独立吉祥物配置。10 月 16 日 `hero-banner-tab.tsx` 有图／视频、深浅资源字段，但它是椭圆单图位；截图对应槽位尚未确认。
- `detect-region.ts` 仅作时区到国家推测，并受 `supportedCountries` 过滤；`invite-code-service.ts` 声明名单由 `/api/ai/invite-code/check` 返回，仅在需要选区时有值。不能通过已绑定用户返回空数组推断没有开放国家。

实现关注：保留国家、时区、当地时间、换算时刻及资源版本；任务按排期版本幂等，读配置时也应检查有效窗口；国家／语言／主题缓存隔离并在到期失效，服务器时间为准。不是仅给前端增加两个日期输入框。

权限、执行记录与报警接现有后台；全局日常为独立资源，节日发布不覆盖它。迁移旧配置时保持日常显示，不把旧全局主题自动发布到所有国家。
